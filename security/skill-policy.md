# Third-party Skill Security Policy

## Обов'язкове правило

Жоден новий сторонній skill не переходить у статус `APPROVED` без перевірки.

## Процес

1. Зафіксувати джерело й точний репозиторій.
2. Перевірити автора, активність і документацію.
3. Переглянути `SKILL.md` та пов'язані скрипти.
4. Запустити SkillSpector.
5. Перевірити:
   - shell-команди;
   - мережеві запити;
   - доступ до файлової системи;
   - читання environment variables;
   - роботу з токенами та secrets;
   - завантаження/виконання стороннього коду;
   - небезпечні або надмірні permissions;
   - приховані інструкції й prompt injection.
6. Спочатку надати статус `TESTING`.
7. Перевірити на некритичному тестовому проєкті.
8. Лише після цього змінити статус на `APPROVED`.

## Заборонено

- запускати невідомі install scripts лише тому, що це радить README;
- передавати secrets сторонньому skill без необхідності;
- надавати write-доступ до всіх репозиторіїв, якщо потрібен лише read;
- автоматично довіряти популярності або кількості GitHub stars;
- встановлювати дубль уже наявного інструмента без конкретної переваги.

## Принцип найменших привілеїв

Skill отримує лише ті права, які потрібні для конкретної задачі.
