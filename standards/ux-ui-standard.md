# Learn4Life UX/UI Standard

## 1. Базовий принцип

Зрозумілість важливіша за декоративність. Інтерфейс має допомагати навчанню й виконанню задачі, а не демонструвати дизайнерські ефекти.

## 2. Anti-AI / anti-slop

Уникати шаблонного AI-дизайну:

- типових hero-блоків без функціональної потреби;
- однакових карток для всього контенту;
- зайвих градієнтів, glow і glassmorphism;
- декоративних орбів та випадкових абстрактних фігур;
- надмірної округлості;
- важких тіней;
- невиправдано великих порожніх зон;
- декоративних ефектів, які не покращують сприйняття.

## 3. Design tokens

Використовувати три рівні токенів:

`Primitive → Semantic → Component`

Приклади:

- Primitive: базові кольори, кроки spacing, розміри шрифтів.
- Semantic: `surface`, `text-primary`, `border-muted`, `action-primary`.
- Component: `button-primary-bg`, `card-padding`, `input-border`.

Не використовувати випадкові hardcoded значення без чіткої причини.

## 4. Візуальна ієрархія

- Один очевидний головний рівень заголовка.
- Одна primary action на екран або логічний контекст.
- Другорядні дії не повинні конкурувати з основною.
- Картки використовувати лише тоді, коли вони справді групують окрему сутність або дію.
- Відступи мають показувати структуру змісту.

## 5. Типографіка

- Обмежена кількість шрифтових ролей.
- Чітка різниця між heading, body, label, helper text.
- Не використовувати надто дрібний текст для важливого контенту.
- Довгі тексти мають мати комфортну довжину рядка.

## 6. Компоненти

Компоненти повинні мати системні стани:

- default;
- hover;
- focus;
- active;
- disabled;
- loading;
- error;
- success, якщо доречно.

Не створювати кілька візуально різних компонентів для однакової функції без причини.

## 7. Іконки

- Одна система SVG-іконок.
- Не змішувати випадкові набори.
- Emoji не використовувати як UI-іконки.
- Emoji допустимі в самому навчальному контенті, якщо це виправдано.

## 8. Accessibility

Мінімум WCAG 2.2 AA:

- достатній контраст;
- видимий focus;
- повна keyboard navigation;
- семантичний HTML;
- зрозумілі labels;
- достатні touch targets;
- не покладатися лише на колір для передачі значення.

## 9. Responsive

Responsive — це не просте зменшення desktop-версії.

На мобільному:

- перебудовувати композицію;
- змінювати порядок блоків, якщо потрібно;
- скорочувати другорядні елементи;
- зберігати зручні touch targets;
- не створювати горизонтальний скрол без функціональної необхідності.

## 10. Motion

Motion використовується лише функціонально:

- показати зміну стану;
- пояснити зв'язок між елементами;
- дати зрозумілий feedback.

Поважати `prefers-reduced-motion`.

## 11. Освітні інтерфейси

- Навчальна задача важливіша за декоративний wow-ефект.
- Інструкції мають бути короткими й знаходитися біля місця дії.
- Результат дії або відповіді має бути очевидним.
- Помилка повинна пояснювати, що сталося і що робити далі.
- Схеми, таблиці та графіки мають передавати зміст, а не заповнювати простір.

## 12. Пріоритет правил

Якщо Taste Skill, інший design skill або генератор пропонує рішення, яке суперечить цьому стандарту, пріоритет має Learn4Life UX/UI Standard.
