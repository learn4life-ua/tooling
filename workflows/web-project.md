# Standard Web Project Workflow

## 1. Ідея

Сформулювати:

- навчальну проблему;
- цільову аудиторію;
- очікуваний результат;
- одну головну дію користувача.

## 2. Прототип

Використати Effective HTML для швидкої перевірки структури й взаємодії.

Результат: не «красива картинка», а працездатна модель інтерфейсу.

## 3. Дизайн

Застосувати:

1. Learn4Life UX/UI Standard.
2. Taste Skill як додатковий design-quality layer.

Внутрішній стандарт має пріоритет.

## 4. Специфікація

Addy Osmani:

`spec-driven-development`

Зафіксувати функції, обмеження, acceptance criteria та edge cases.

## 5. План

`planning-and-task-breakdown`

Розбити роботу на невеликі перевірювані частини.

## 6. Реалізація

`incremental-implementation`

Для UI:

`frontend-ui-engineering`

Не переписувати великий шматок проєкту без потреби.

## 7. Візуалізації

Diagram Design використовувати для:

- flowcharts;
- timelines;
- architecture diagrams;
- process diagrams;
- educational схем;
- інших структурних візуалізацій.

## 8. Перевірка

`browser-testing-with-devtools`

Перевірити:

- console;
- network;
- DOM;
- responsive;
- keyboard navigation;
- accessibility;
- performance.

## 9. Виправлення

`debugging-and-error-recovery`

Помилку потрібно відтворити, локалізувати, виправити й перевірити повторно.

## 10. Фінальний контроль

- `code-review-and-quality`
- `security-and-hardening`
- `performance-optimization` за потреби.

## 11. Робота з великим існуючим проєктом

Перед значними змінами використовувати Understand Anything для побудови картини структури й залежностей.

## 12. Новий сторонній skill

Спочатку застосувати `security/skill-policy.md`.
